# Leo — Multi-Agent AI Tutor

Leo is a study assistant built from four specialized AI agents that collaborate — planning, teaching, quizzing, and evaluating — to run a full tutoring session for a student on any topic they choose.

Built with **CrewAI**, powered by **Groq (llama-3.1-8b-instant)**, run via a **CLI interface**.

## Agents & Roles

| Agent | Role | Responsibility |
|---|---|---|
| **Coordinator** | Session Coordinator | Reads the student's raw request, determines a clear topic and skill level (beginner/intermediate/advanced). If the request is too vague, it asks a clarifying question instead of guessing. Does not teach, quiz, or grade. |
| **Explainer** | Concept Explainer | Teaches the topic clearly, adapted to the student's level, with one concrete example. Does not quiz or grade. |
| **Quiz Master** | Quiz Master | Writes exactly 3 practice questions based on what the Explainer just taught, with a structured `Q:`/`ANSWER:` output format so downstream code and the Evaluator can parse it reliably. |
| **Evaluator** | Answer Evaluator | Grades the student's typed answers against the Quiz Master's answer key, gives per-question feedback (CORRECT/PARTIAL/INCORRECT), an overall summary, and a list of weak areas. It's also instructed to sanity-check the answer key against its own knowledge, since the key was generated by another LLM and can occasionally be imperfect. |

Each agent has its own dedicated `role`, `goal`, and `backstory` (in `prompts/`), and only performs its own job — none of them teach, quiz, or grade outside their lane.

## Orchestration Pattern

**Sequential pipeline**, coordinated by plain Python (not CrewAI's built-in hierarchical manager):

```
Coordinator → Explainer → Quiz Master → [student answers, human-in-the-loop] → Evaluator
```

The Coordinator step includes a **clarification loop**: if the student's request is unclear, the Coordinator asks a follow-up question, the student responds, and the Coordinator re-evaluates — repeating until the request is clear enough to proceed. This is how Leo satisfies the "Coordinator manages unclear/ambiguous requests" requirement.

Each stage runs as its own single-task `Crew` with `Process.sequential`. The "orchestration" logic — deciding what happens after each agent finishes, and what data moves to the next step — lives in `main.py`, using a shared `SessionMemory` object as the handoff mechanism (see below).

## Memory

`memory.py` defines a `SessionMemory` dataclass that holds all session state:

- `student_name`, `topic`, `student_level`, `notes` — set by the Coordinator
- `explanation` — set by the Explainer
- `quiz_questions` — set by the Quiz Master (includes the answer key)
- `student_answers` — set from CLI input
- `feedback`, `weak_areas` — set by the Evaluator
- `history` — a running log of every agent's output, useful for debugging and the transcript

This is intentionally a plain Python object rather than CrewAI's built-in RAG-based Memory feature — it's simpler, fully transparent/debuggable, and sufficient for a single tutoring session that doesn't need semantic recall across many past sessions.

`SessionMemory.as_dict()` converts the object into keyword arguments used to fill each agent's prompt template via `.format(**session.as_dict())`.

## Prompt Templates

Each agent has its own file under `prompts/` with two parts:
- `*_BACKSTORY` — the agent's role definition and boundaries (used as the CrewAI `Agent`'s `backstory`)
- `*_TASK_TEMPLATE` — a reusable prompt template with `{placeholders}` filled per-session from `SessionMemory`

Example (`prompts/explainer.py`):
```python
EXPLAINER_TASK_TEMPLATE = """
Topic to teach: {topic}
Student level: {student_level}
Coordinator notes: {notes}
...
"""
```

Keeping templates in separate files (rather than inline in agent definitions) makes each role's exact instructions easy to inspect and grade independently.

## Handoffs

A "handoff" in Leo means: **one agent's raw text output is parsed in Python and written into `SessionMemory`, then the next agent's prompt template reads those same fields back out.**

Example — Coordinator → Explainer:
1. Coordinator outputs raw text: `TOPIC: binary search trees\nLEVEL: intermediate\nNOTES: ...`
2. `parsing.py`'s `parse_coordinator_output()` extracts this into a dict: `{"topic": ..., "level": ..., "notes": ...}`
3. These values overwrite `session.topic`, `session.student_level`, `session.notes`
4. The Explainer's task template is filled using `session.as_dict()`, so it receives the Coordinator's cleaned-up values, not the student's original raw request

The same pattern repeats for Explainer → Quiz Master (via `session.explanation`) and Quiz Master → Evaluator (via `session.quiz_questions` and `session.student_answers`, the latter built by `parsing.py`'s `format_student_answers()`).

## Error Handling

- **Unclear requests**: handled by the Coordinator's clarification loop (see Orchestration Pattern above) rather than the pipeline guessing or crashing.
- **Malformed LLM output**: the Quiz Master is explicitly instructed to output single-line questions only (no diagrams/code blocks), since early testing showed multi-line questions broke the line-based parser — a real constraint discovered during development.
- **Imperfect answer keys**: the Evaluator is instructed to sanity-check the Quiz Master's answer key against its own knowledge rather than trust it blindly, since it's LLM-generated and occasionally imperfect.

## How to Run

```bash
pip install -r requirements.txt
```

Create a `.env` file (not committed) with:
```
GROQ_API_KEY=your_groq_api_key_here
```

Then run:
```bash
python main.py
```

Follow the prompts: enter your name, describe a topic, answer the quiz questions when asked.

## Tech Stack

- **CrewAI** (`Agent`, `Task`, `Crew`, `Process.sequential`) — agent framework and orchestration
- **Groq** (`llama-3.1-8b-instant`) via LiteLLM — the underlying LLM
- **Python** `dataclasses` — session memory
- **CLI** — interface, with per-agent status messages (e.g. "Coordinator is reviewing your request...") so the user can see which agent is active at each step

## Known Limitations

- **Non-determinism**: LLM outputs vary between runs — the same topic can produce different (but equally valid) explanations and questions each time.
- **No independent fact-checking between agents**: each agent trusts the previous agent's output. A flawed Quiz Master answer key could mislead grading if the Evaluator's sanity-check instruction doesn't catch it.
- **No re-teach loop implemented** (bonus feature) due to time constraints — the Evaluator does produce a `WEAK_AREAS` field that would support this if extended.
